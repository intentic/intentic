## The problem it solves

Three things about a desktop app cannot be checked by any amount of unit testing: that the installer
resolves its own dependencies, that the app survives startup, and that an `intentic://` link reaches
it. Each is green on the maintainer's machine by construction — it already has every library, and it
already has the app running. So this is a container with a display and nothing else.

## What is deliberately not installed

No graphics libraries. That is the whole point: the Debian package's dependency list is generated by
the bundler, nothing else in the pipeline reads it, and an incomplete one is green all the way to a
user's first launch, where it is a linker error they cannot act on. Pre-seeding the libraries would
hide exactly the bug this exists to catch.

The deep link is fired twice, at an app that is running and at one that is not, because those share
the link and almost no mechanism — and the second is the state a machine is in the moment somebody
installs and clicks "set up". Assertions read window *titles* through `xdotool` rather than a test
hook, because the failure worth catching is a link that is won and then dropped: the app starts, sees
no url, and opens on the workspace. A window appears either way; only the title says which screen.

## Where it is used

Run from `_tools/scripts/verify-desktop-install.sh` in CI. The Windows installer is not covered here —
running it needs Windows.
