# e-Doręczenia

Use `$EDORECZENIA_UA_URL` for User Agent API v3 and `$EDORECZENIA_SE_URL` for Search Engine API v4. SE API searches the **BAE** address register for an **ADE** (adres do doręczeń elektronicznych); UA API handles messages, their attachments, mailbox operations and delivery evidence. The [government API page](https://www.gov.pl/web/e-doreczenia/interfejsy-api) gives the current versions and [UA v3 OpenAPI download](https://edoreczenia.poczta-polska.pl/wp-content/uploads/2026/05/uaapi_3.0.8.2.zip). That specification lists `GET /{eDeliveryAddress}/messages`, `GET /{eDeliveryAddress}/messages/{messageId}`, `GET /{eDeliveryAddress}/messages/{messageId}/evidences`, and `GET /{eDeliveryAddress}/messages/{messageId}/attachments/{attachmentId}`. Read the exact operation, fields and proof type from the deployed version's specification before calling it. Preserve returned **UPD/UPO** evidence with the associated message; do not infer delivery from a successful send response.

The office must register its external system and grant roles in **Moduł uprawnień**. The [official INT integration instruction](https://www.gov.pl/attachment/b0bbf5ef-8909-43ff-851d-d1183e96d02a) describes certificate-based RFC 7523 authentication: create a short-lived JWT whose `iss` and `sub` combine the office ADE, `.SYSTEM.`, and registered system name; set the authority audience, `iat`, `nbf`, `exp` and unique `jti`; sign it with the system certificate's private key; POST it as `client_assertion` with `client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer` and `grant_type=client_credentials` to `$EDORECZENIA_TOKEN_URL`, including the ADE `login_hint` required by the registered environment. Send the returned access token as `Authorization: Bearer` to UA/SE. Confirm the audience and token URL against that environment's current instruction; the INT PDF includes sample values, not universal PROD constants. The [government integration page](https://www.gov.pl/web/e-doreczenia/integracja-uslugi-e-doreczen) explains INT access and registration.

The certificate and key arrive as multiline environment variables. If a client needs PEM files, create them in a private temporary directory with mode `0700`, write each with mode `0600`, use it for this call, and remove the directory in a cleanup trap. Never print the PEM, JWT or access token. The connector does not perform an authenticated probe because one requires a signed assertion and a registered system.

Search ADE addresses and read received messages, attachments and proofs as needed. Prepare an outgoing formal delivery with exact recipient ADE, sender ADE, message, attachments, service and expected proof in a `kind: "action"` approval file under `.intentic/config/approvals/`, following the approvals skill. **Never invoke UA API's send operation directly**. The approved fresh turn must recheck the recipient in BAE, send only the approved material, and save the returned proof. If the versioned specification or registration parameters are unavailable, stop at a draft and report the missing item.
