# @intentic/ext-documentation

Plain-language architecture documentation for every repository and package in the workspace: generated by agents,
reviewed by the owner, committed into the repo it describes, and checked for rot afterwards.

## The one decision everything else follows from

**A document is markdown with typed figure fences — not HTML, and not a JSON document model.**

- **Not HTML.** Agent-authored HTML renders in a locked-down `srcdoc` iframe (the `DirectoryUiHost` path), which is
  an opaque origin: it cannot see the design tokens, dark mode, or fonts, so every page becomes a separate little
  website. Charts would need a CDN fetch that fails offline. A 900-line generated HTML diff is unreviewable. And
  staleness would have to be parsed back out of HTML comments instead of read from a field.
- **Not a fat JSON model.** `responsibilities: string[]` + `flows: [{ steps }]` forces every explanation into one
  predeclared shape, splits the narrative from the figures that belong inside it, and makes an unreadable JSON diff
  the review surface. It also degrades worse: a malformed figure costs the page instead of costing one figure.

So prose is prose, figures are inline fences the app renders as components, and the JSON alongside carries only
what the app must *read* rather than draw: identity, the map, anchors, provenance.

## Three layers, kept apart

| Layer | Produced by | Why there |
| --- | --- | --- |
| **Facts** — package graph, sizes, revisions | `bin/intentic-docs` | a script is exact and free; a model is plausible and wrong |
| **Judgement** — what a thing is for, which packages form a component, what to read first, what surprises | the agent, in `doc.md` / `repo.md` + a few JSON fields | the only part that needs a mind, and the only part worth reviewing |
| **Presentation** — theme, layout, dark mode, dagre, a11y | the app (`@intentic-app/ui`) | nothing authored carries a colour, a coordinate or a size |

## Where documents live

```
<repo>/docs/architecture/          PUBLISHED — in git, reviewed, travels with a clone
├── repo.json                      the map: components, glossary, reading order  (authored)
├── repo.md                        the repository's page, prose + figures        (authored)
├── index.json                     staleness / orphans / coverage                (GENERATED — never by hand)
└── <pkg-dir>/{doc.json,doc.md}    one directory per package, mirroring its path (authored)

.intentic/docs/<repo>/…            STAGED — same tails, a draft awaiting the owner
```

Two trees because generation and reading want different things. Staging is a workspace-root path, so N isolated
agents can write into it at once and it can ride the daemon's file-change push (`contributes.files`) — an in-repo
path cannot, because a manifest is static and repo names are not known when it is written. Publishing is then a
copy per tail, never a translation, plus one commit the owner asked for.

## Generation is map-first

1. **Map phase** — one agent runs `intentic-docs facts`, then writes `repo.json` + `repo.md`: the logical
   components, the repo's vocabulary, the reading order. Nothing else can decide those; they are cross-package
   judgements, and 42 agents deciding independently produce 42 vocabularies and no map.
2. **Fan-out** — one isolated agent per package, each handed *its* component and the shared glossary inline.

Advancing between the phases is **idempotent and derived**: a package's agent starts only when there is neither a
fleet entry for its (derived) conversation id nor a staged document for it. Closing the browser mid-run does not
orphan it, and nothing is ever started twice.

## Rot is detected, not assumed

`provenance.sourceRev` records the revision a document was written against. `intentic-docs check` compares it and
writes the verdict to `index.json`, catching three kinds of decay:

- **behind** — commits have touched the package since it was documented
- **dead anchor** — a `keyFiles` path no longer exists (the one signal that needs no git history and cannot be argued with)
- **orphan** — a document whose package is gone (invisible to a revision comparison: there is no dir left to have one)

Staleness is computed by the tool rather than the browser because `GET /git/{repo}/log` takes no path filter, so
the browser would need one commit-diff request per commit.

The real anti-rot mechanism, though, is the shipped skill: **update a package's document in the same commit as the
change that invalidated it.** The checker is the backstop for what slips.

## The URL is the state

`/ext/documentation?repo=<repo>&doc=<package-dir>` — which document is open lives in the query, so a page can be
linked to and a reload lands where you were. The view *derives* its selection from the URL rather than mirroring it
into a ref: mirroring needs one watcher to follow the URL and another to write it, and those two fight (the
classic symptom being Back moving the URL while the view stays put). Selecting a page pushes a history entry;
choosing a repository replaces one and clears `doc`, because a document path only means something inside its own
repository.

The published/draft toggle is deliberately **not** in the URL. A draft is one person's unreviewed work in progress,
so a link carrying "show me your draft" would either mislead the recipient or show them nothing.

This rides on `api.route` in the public extension API, added for this view because `/ext/:ext/:key?` has exactly one
free path segment and it already means "which activation" — a view with internal navigation has nowhere else to put
it. See `_libs/extension-api/src/route.ts` for the query rules and `route.test.ts` for the invariant that matters:
patching your own key never disturbs another view's.

## Gotchas

- `bin/intentic-docs` duplicates two path constants from `src/paths.ts` — it is plain ESM executed directly by the
  agent's shell, so it cannot import TypeScript. `paths.test.ts` pins them together so the duplication cannot drift.
- The `directory` surface activates for **every** repo, because `detect()` is synchronous over the public facts and
  cannot read a file. The honest refinement is a `docs` fact on `RepoFacts`, one line beside `userStories` in the
  daemon's panels route.
- Publishing commits the whole index. Anything already staged in the repo rides along, and the wire cannot tell us
  otherwise (`GitStatus.files` is porcelain that the daemon has already `.trim()`ed, which destroys the staged
  column). The confirmation names the number of unrelated changes instead of pretending to precision.
