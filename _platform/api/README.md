# @intentic-app/api

The **platform backend** — Hono + oRPC + Prisma + Better Auth. The platform is an **identity + sandbox-URL store**: it authenticates the user (Google) and stores the sandbox URL the browser tells it so the browser can reach the sandbox directly. It never probes the sandbox or tracks liveness and owns no infrastructure; it sits **off the command path with exactly one exception** — the free trial ([src/trial/](src/trial/)) — and the browser otherwise talks to the sandbox daemon directly over the sandbox's own tunnel. Runs under `tsx` in dev on :6480 (the web dev-server proxies to it). Consumes [`@intentic-app/api-contract`](../../_platform/api-contract) (`implement`) + [`@intentic-app/prisma`](../../_platform/prisma).

## Responsibilities

- Authenticate the user (Better Auth + Google) and expose the typed oRPC surface (`me`, `setup.*`).
- Mint the per-user connection token + serve the setup one-liner. The workspace gate is enforced in the browser, which probes the daemon's `/health` directly — the platform never decides liveness.
- Store the sandbox's public `daemonUrl` the **browser** derives (`sandbox-<sha256(token)[:12]>.<zone>`) and writes (`setup.bind`), and serve it back (`setup.binding`) so the browser knows where to reach it. Persist nothing else about the sandbox.
- Serve the **free trial** ([src/trial/](src/trial/)): an OpenAI-compatible model API on intentic's own free-tier keys, so a user can chat before connecting any AI account. Metered per signed-in account per UTC day (`TrialUsage`), authenticated by the sandbox's connect token. It publishes **one synthetic model id** and picks the real model per message from a curated ladder ([trial-ladder.ts](src/trial/trial-ladder.ts)) — discovery may only remove rungs from that ladder, never add to it, because Google declares `generateContent` for models that cannot serve an agent turn. The pool walks **(key, model) pairs** under one deadline, since quotas are metered per model: bounded header timeouts, short refusal quarantines, failover across both dimensions. Unsuccessful completions are refunded, `/trial/status` reports the health observed by real chat traffic and the model that last answered this account. **Off by default** — no `TRIAL_KEYS`, no trial.
- Run the **creator pool** ([src/pool/](src/pool/)): the paid membership (Stripe checkout/portal/webhook — Stripe stays the money's source of truth, `Membership` is the local mirror; `POOL_COMP_EMAILS` grants premium without one — complimentary members ride the same daily meter but add nothing to the pool's revenue or member count, and it is local dev's way to a runnable paid flow), the **install donation** a premium extension earns by (`Donation`, deduped per user/extension/month — the platform's ONLY signal about non-service extensions; no usage telemetry exists), and the **public transparency read** that states member count, the split, and every recipient's credits and earnings. The shares are levied on the membership **after** `POOL_INFRA_USD` of per-member running cost comes off the top ([pool-share.ts](src/pool/pool-share.ts)), and a credit is priced off that remainder rather than the ticket — so the published share stays literally true of the pool it names, and the transparency read carries the infrastructure line beside the gross it came out of rather than folding it in. **Off by default** — no `POOL_STRIPE_SECRET_KEY` + `POOL_STRIPE_PRICE_ID`, no pool.
- Meter **credit spends** ([src/pool/pool-credits.ts](src/pool/pool-credits.ts), [pool-services.ts](src/pool/pool-services.ts)): members get a daily credit allowance (the trial meter's atomic spend-then-refund shape) that both donations and service runs draw from. A run spends a service's published price, is forwarded to the provider's upstream with a timestamped HMAC (the Stripe-webhook scheme in reverse — the platform is the intermediary, so the provider verifies origin instead of identifying the user), and the provider answers by STREAMING NDJSON in the contract's ServiceStreamEvent vocabulary — validated line by line at this trust boundary, relayed live, and closed with the platform's own `receipt` trailer; a stream that dies before its `result` (like a 5xx or a timeout) is refunded with the run row saying so. Every spent credit pays its recipient a published share of its value on the same transparency read.
- **Hold the keys a sandbox must not** ([src/wallet/](src/wallet/)): a sandbox agent can pay x402-charging endpoints in USDC, and the container it runs in is not a key boundary (its daemon and its agent are one root process tree), so the wallet lives here — one per member per network, owner-scoped and never pooled, with the key itself held by a custody provider ([wallet-custody.ts](src/wallet/wallet-custody.ts)) so the platform stores no key material either. Every signature is checked against **this** database rather than against anything the sandbox claimed: the wallet is the caller's, the token is USDC, the stated amount matches what the authorization moves, the validity window is short, and the per-payment ceiling and UTC-day cap both hold — the day's row is written inside the same serializable transaction that reads the day's total, so two turns cannot race one budget. The sandbox's own checks are the UX; these are the guarantee. **Off by default** — no `WALLET_CUSTODY_URL` + `WALLET_CUSTODY_KEY`, no wallet.
- Admit services **without an operator** ([src/pool/pool-admission.ts](src/pool/pool-admission.ts), [src/creator/creator-services.ts](src/creator/creator-services.ts)): a provider drafts a listing, and passing three mechanical gates lists it immediately — a claimed publisher name plus payouts enabled (a name is proved from a registry-listed repository, or — the dot is the discriminator — as a **domain**, by serving the derived token at `/.well-known/intentic-claim`; [src/creator/creator-claim.ts](src/creator/creator-claim.ts)), a live **conformance probe** (one signed call that must serve, plus a forged one and an expired one that must both be **refused** — an endpoint that answers a forgery can be billed by anyone), and bounded listing rules (price band, reserved words, public https endpoint — and a domain publisher's endpoint must live on its own domain, so the name on the card and the host serving the runs are the same party). Every threshold is config, never a constant, because rules a provider cannot look up in advance are a human review wearing a constant's clothes. A `Service` row's `status` (`draft` → `probation` → `listed`, `suspended`) replaced the old `active` bit: new listings go live **on probation** under a tighter price ceiling and badged on every card, and [pool-watch.ts](src/pool/pool-watch.ts) graduates them on a served-run counter, suspends any listing whose recent refund rate exceeds the published rate, and re-probes quiet ones on the daily cycle. Operator rows (`userId` null — the demo behind `POOL_DEMO_SERVICE`, [pool-demo.ts](src/pool/pool-demo.ts)) are exempt from all of it; the demo's request picks its outcome test-card style (`scenario`: ok / slow / refuse / fail / broken, `paceMs` for tempo), so every settlement a member's card can show is reproducible on demand, and [pool-conformance.test.ts](src/pool/pool-conformance.test.ts) drives the real probe and the real forward against the copyable reference endpoint ([\_platform/example-provider](../example-provider/)) so the gates and the starter code cannot drift apart. Off with `POOL_OPEN_ADMISSION=false`. Design: [docs/services-admission-design.md](../../docs/services-admission-design.md).
- Run the **push relay** ([src/push-relay/](src/push-relay/)): APNs forwarding for the iOS shell ([\_editor/ios-app](../../_editor/ios-app)), the one notification path that cannot go direct — Apple only accepts pushes from the app's vendor, so the daemon posts plain JSON here and the relay signs it on to APNs ([apns.ts](src/push-relay/apns.ts)). The capability model keeps both sides minimal: the signed-in app registers the device token and gets back `{deviceId, secret, url}`, which it stores on the DAEMON as the channel; a send is sessionless and proved by the secret alone (stored hashed), so the relay never learns which sandbox is calling and the daemon never holds an Apple credential. Refusals speak the daemon's own dead-channel codes (403/404/410) so its pruning works unchanged, and a notification's title/body pass through **readable** — the stated privacy trade against web push's end-to-end encryption; the payloads are pointers back into the workspace by design, never content. Android needs none of this: the Play app is a TWA riding ordinary web push. **Off by default** — no `APNS_KEY_P8`, no relay; the routes 404 and the shell reports notifications unsupported.
- The setup wizard's **cloud lane** ([src/sandbox/cloud/](src/sandbox/cloud/)): create ONE VM in the **user's own** cloud account (Hetzner / DigitalOcean / Oracle Always-Free) whose first boot runs the sandbox's setup code. The pasted provider credential is request-scoped like the Cloudflare zone listing — spent on the provider's catalog + create calls, never persisted — so the platform keeps no way back into the machine; only display metadata (`Sandbox.cloud`) survives.
- Run the **hosted lane** ([src/sandbox/hosted/](src/sandbox/hosted/)) and **pay for what it costs**: one Fly machine + volume per sandbox on intentic's own credential, and the two mechanisms that stop a free machine costing forever. **Awake hours** ([hosted-usage.ts](src/sandbox/hosted/hosted-usage.ts)) are metered per owner per calendar month (`HostedUsage`) against `HOSTED_MONTHLY_HOURS` and enforced **at wake, never mid-session** — members are exempt entirely. The platform stamps the start of every stretch because it performs every wake, and closes it later by asking Fly when the machine stopped, since the machine sleeps from the inside and tells nobody. **Idle collection** ([hosted-idle.ts](src/sandbox/hosted/hosted-idle.ts)) destroys a non-member's machine and disk after `HOSTED_IDLE_DAYS` unopened, one warning email earlier, never taking a machine that is currently running (`Sandbox.lastSeenAt` is a BOOT announce, so a long-running box reads as untouched) and never taking a member's. Both sweeps ride the daily [retention.ts](src/retention.ts) job. A **warm pool** ([hosted-pool.ts](src/sandbox/hosted/hosted-pool.ts)) can pre-build `HOSTED_POOL_SIZE` machines per region — image pulled by a no-op first boot, then stopped, holding no identity — so a claim writes the sandbox's env into one and starts it in seconds instead of pulling the image on demand; a five-minute reconcile — nudged immediately after every claim, so a spent slot starts rebuilding without waiting out the tick — keeps the pool at size (a small stock per region by default), rebuilds it when the image moves, and drains it when switched off. A pool machine's app is named `<prefix>-pool-<hex>` before anyone asks for it and Fly lets neither an app nor a machine be renamed, so a claimed machine wears a pool name for life and the Fly console's app list can never tell stock from a person's sandbox: every machine therefore carries a Fly **metadata stamp** of what it currently is (`intentic_role`, rewritten with the config at claim — the one label the provider can be asked about and filtered on), and `pnpm --filter @intentic-app/api fleet` ([hosted-fleet.ts](src/sandbox/hosted/hosted-fleet.ts)) prints the readable version by joining Fly's app list against the platform's own rows: taken (with owner), warm, claiming, orphaned. **Off by default** — no `HOSTED_FLY_API_TOKEN`, no hosted lane.

## Routes (see [src/app.ts](src/app.ts))

- `/api/auth/**` — Better Auth (Google OAuth redirect, the browser-minted Google ID token at `one-tap/callback`, session).
- `${API_BASE_PATH}/*` — the oRPC OpenAPI handler ([src/router.ts](src/router.ts): `me`, `setup.connect`, `setup.zones`, `setup.bind`, `setup.binding`). `bind` stores the browser-derived `daemonUrl`; `binding` reads it back.
- `/trial/*` — the free trial's model API (`/trial/status`, `/trial/v1/models`, `/trial/v1/chat/completions`), authenticated by the sandbox connect token. 404s entirely when `TRIAL_KEYS` is unset.
- `/pool/*` — the creator pool's non-browser routes: the daemon's ledger report + premium probe (connect-token), the services catalog + metered `POST /pool/services/:slug/run` + the wanted-list write `POST /pool/wanted` (connect-token — an agent's "the catalog had nothing for this", length-bounded and capped per owner per day, published only in aggregate), Stripe's webhook (signature), and the two public reads: `GET /pool/transparency` and `GET /pool/catalog` (the live listings with each one's served/refunded run counts, plus the wanted aggregate — the site renders both cross-origin). The browser half (membership state + credits, checkout, portal) rides the oRPC contract. 404s entirely when the pool is unconfigured.
- `/wallet/*` — the agent wallet's signer ([src/wallet/](src/wallet/)), connect-token authenticated: `POST /wallet/ensure` create-or-return this member's USDC wallet and mirror the sandbox capability card's caps onto it, `POST /wallet/sign` mint one EIP-712 signature over one fully-specified EIP-3009 transfer. 404s entirely when `WALLET_CUSTODY_URL` + `WALLET_CUSTODY_KEY` are unset.
- `/health` — DB connectivity.

## Key files

- [src/main.ts](src/main.ts) — entrypoint: `serve(...)`.
- [src/app.ts](src/app.ts) — the Hono app factory + all route wiring; [src/router.ts](src/router.ts) + [src/context.ts](src/context.ts) — oRPC.
- [src/auth.ts](src/auth.ts) — Better Auth (Google sign-in + the desktop one-time-token handoff). Sign-in has
  two doors on purpose: the OAuth redirect, and `one-tap/callback`, which takes a Google ID token the BROWSER
  minted. The second exists because the sandbox authenticates people against Google itself and does not trust
  this platform — so only a credential the browser holds can serve both, and asking for Google twice was
  costing sign-ups. It makes the platform a second CONSUMER of that credential, never its issuer.
- [src/sandbox/cloud/index.ts](src/sandbox/cloud/index.ts) — the cloud lane's provider switch; one plain-fetch adapter per provider beside it (Oracle's request signing in [src/sandbox/cloud/oci-sign.ts](src/sandbox/cloud/oci-sign.ts), the first-boot script in [src/sandbox/cloud/user-data.ts](src/sandbox/cloud/user-data.ts)).
- [src/config.ts](src/config.ts) — `@puristic/env` config; [src/prisma.ts](src/prisma.ts) — client factory; [src/types.ts](src/types.ts) — the shared Prisma type.

## Conventions & gotchas

- The platform is **off the command path except for the free trial** — there is no relay, no socket to the sandbox, and no sandbox-originated calls other than the daemon's announce and its trial probe. The browser calls the sandbox daemon directly (authenticated by the user's Google ID token); the platform only holds the stored URL. Trial turns are the one thing that passes through, they are labelled as such in every surface that offers them ([`TRIAL_NOTICE`](../../_sandbox/sandbox-contract/src/agent-catalog.ts)), and connecting any account takes the user off that path for good.
- **Four documented secret exceptions**, all intentic's own credentials and all optional: `INTENTIC_CLOUDFLARE_API_TOKEN` (provisioning sandbox tunnels for users who bring no Cloudflare), `TRIAL_KEYS` (the free-trial pool), `POOL_STRIPE_SECRET_KEY`/`POOL_STRIPE_WEBHOOK_SECRET` (the creator pool's Stripe account), and `APNS_KEY_P8` (the push relay's Apple key — the narrowest: only notification titles/bodies pass through). Everything else — Claude/git tokens, SSH keys, the user's Cloudflare — lives in the sandbox.
- `setup.connect` returns only the connection token + the connect-script URLs. The sandbox's public URL is **derived deterministically** from that token + the chosen zone (`sandbox-<sha256(token)[:12]>.<zone>`, matching the CLI's tunnel hostname) and written by the browser via `setup.bind` — the sandbox never calls the platform.
- Config is nested + SCREAMING_SNAKE-derived by `@puristic/env`; secrets are plaintext in the DB for now. No platform test harness — verify with `pnpm build` + `pnpm lint`.
