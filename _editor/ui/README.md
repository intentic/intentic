# @intentic/ui

Shared **Vue UI primitives + theme** for the platform web app. A small, reusable layer on top of PrimeVue + Tailwind 4 that [`@intentic-app/web`](../../_editor/web) composes: layout containers, a code/markdown primitive, the dark/light theme composable, and the design tokens.

## Responsibilities

- Provide primitives: `Page` (centered, width-constrained shell), `Card`, `ScrollFrame` (the bordered pane that scrolls its own body), `Code` (Shiki-highlighted block), `CodeField` (the same colours with a caret in them, the editable source surface), and `InfoHint` (hover/focus info card).
- Own theming: `useTheme` (dark/light `ColorScheme` + the accent colour, both persisted) + `installUi(app)` (the single design-system plugin: PrimeVue preset + cssLayer order + tooltip directive) + the `Theme` preset.
- Own the app's colour: the reader picks ONE, with `ColorPicker`, and `themeColor.ts` expands it into the twelve-step brand and neutral ramps every surface, border, link and fill resolves through, written as inline custom properties on `<html>`, so the whole UI repaints without a rebuild. The step LIGHTNESSES are fixed (they are what the contrast promises in `semantic-colors.css` are made of); a picked colour sets hue everywhere and how much chroma the ladders carry.
- Own how large the app reads: `useTextSize` (persisted, `compact`/`default`/`large`). Because every size in the tokens is a rem, this one knob moves type, spacing, control heights and radii together, `default` is the 110% the interface is drawn at, so a fresh window needs no browser zoom. It also publishes `--ui-scale`, which anything that must NOT grow divides by (the web app's navigation rail) and anything that paints its own text multiplies by (Monaco, xterm).
- Own the one markdown surface: `Markdown` renders sanitized prose, Shiki-coloured fenced blocks, and the fences that are FIGURES rather than code, `dag`/`bars`/`stats`, whose bodies are JSON the app lays out, and `mermaid`, which mermaid itself draws (lazily imported, in the app's own palette). A fence the renderer cannot understand stays a code block, so a broken figure costs itself and not the page. The engine renders a document as PARTS (prose runs plus the figures between them), which is what lets a surface with its own rendering, the chat transcript, which splits a live turn into a settled prefix and a still-writing tail, draw the same figures without giving up the split. The two heavy renderers load on demand: mermaid on the first document that holds a diagram, the graph canvas (Vue Flow + dagre) on the first that holds a `dag`.
- Own every box that OPENS: `Modal` (the app's one centred dialog, in four named sizes plus `full`, each token carrying its own viewport clamp, `ConfirmDialog` and `InfoDialog` are built on it), `AnchoredOverlay` (a panel pinned to a trigger, placed against the window that trigger is in) and `ResponsiveOverlay` (the same panel, a bottom sheet on a phone, behind one open flag). Nothing outside the kit should reach for PrimeVue's `Dialog` or `Popover`: both measure against the module-scope `window`, which is the wrong one in a popped-out panel.
- Own the one way the app says something went wrong: `Notice`, a tinted box with an icon, an ARIA role and at most one action, taking either a `NoticeModel` (a failure turned into a sentence) or a slot (a message the view wrote as markup). `NoticeStack` ranks several by severity and collapses repeats.
- Own the two shapes an extension screen turns out to be twice: `NoteEditor` (one markdown note, read and curated, the Copy/Edit/Delete cluster, the in-place delete confirmation, and the one surface a file is both read and written on) with `useNoteDraft` behind it, and `RepoRail` (the narrowing "which repository" column, with the pinned "all" row and the same rail folded into a `Picker` once the split is too narrow). Knowledge and Memory had built the first twice; Maintenance and Pipelines the second, and in both pairs the copies had already drifted.
- Provide `vTw` (the `v-tw` Tailwind class-merge directive), `ui` (the Tailwind class recipes: `ui.input()`, `ui.sectionLabel()`, `ui.iconButton()`) and `useHighlighter` (the shared Shiki highlighter).
- Own what one COMPUTER's sandboxes look like, because two apps draw them: `MachineDetail` (one row per sandbox, its folder, its localhost ports, its image, its container's state), `SandboxVerbs` (which buttons that row has, in which order, in which words, and which single one is red) and `MachineRunLog` (the machine's own output under a row that is working). The web app's Computers tab and the desktop app's manager window manage the same containers on the same machine, and every one of these three began as one app's copy that the other then diverged from, a log tail here and a Restart there, one card list drawn twice, two different sentences asking about the same deletion. The callers keep only what genuinely differs: how a click reaches that machine.
- Own the one button that starts an agent for you: `AgentRunButton`, a split button whose primary half runs on the sandbox's standing agent-run model and whose caret re-points that single run, plus `useAgentRunPick`, the state behind it. Six surfaces press it (both Fix buttons, Maintenance, Documentation, Acceptance, and a failed pre-push check), and before it existed each had reached a different answer about how you choose what a click spends. The picker itself is NOT here: it is a live read of connected accounts and catalogs, so the caller passes it in as `ModelPicking` and the kit stays free of both the app's state and the extension API.
- It is **presentational/shared only**: no app state or data fetching.

## Key files / exports

- [src/index.ts](src/index.ts), the public surface, and the kit's own map: nearly every export carries a note saying what it replaced and why it exists. Read this before adding a component; the thing you want is usually already here under a name you did not guess.
- [src/components/](src/components): the `.vue` components, each with an optional plain-TypeScript sidecar of the same name in camelCase (`Picker.vue` + `picker.ts`) holding its types and pure logic, so a unit test can reach them without booting a DOM.
- [src/markdown/](src/markdown), the engine behind that surface, on the `@intentic/ui/markdown` subpath because it is plain TypeScript: `render.ts` (sanitize, the document's parts, and the streaming split), `code.ts` (fenced blocks), `figures.ts` (which fences are figures).
- [src/lib/](src/lib), everything that is plain TypeScript rather than a component or a composable: the colour maths (`oklch.ts`, `themeColor.ts`, `brandColor.ts`), `format.ts`, `path.ts`, `timeWindow.ts`, `ui.ts` (the class recipes), `anchorPlacement.ts` (where an anchored box goes, measured against the anchor's own window) and the `tooltip.ts` directive. Most of these also ship as their own subpath export, so a node-environment test can import one without the component barrel.
- [src/plugin.ts](src/plugin.ts) (`installUi`) and [src/composables/](src/composables), `use*` composables ONLY, which is the rule: `useTheme` (scheme + accent refs, persistence, and the inline custom properties that carry the accent), `useTextSize` (also on the `@intentic/ui/text-size` subpath, so plain modules can ask how large the app is without booting the component graph), `useHighlighter` (lazy Shiki core; also on `@intentic/ui/highlighter`). Anything here that is not reactive state belongs in `lib/`.
- [src/styles/](src/styles): design tokens + `theme.ts` (the `Theme` preset that bridges Tailwind vars ↔ PrimeVue `--p-*`), PrimeVue overrides (`@layer primeng`), semantic colors. `index.css` is the whole design system in one import; `opt-in/` holds the two sheets only some consumers pay for (`prose.css`, `extension-surface.css`).

## How it fits

Consumed by the web app: `installUi(app)` runs once in `main.ts`; components import `Card`/`Page`/`Code`/`InfoHint` and use `useTheme` for the scheme toggle, `useHighlighter` for code, `v-tw` for conditional classes.

Also consumed by the [desktop app](../desktop-app), which is the reason a few of these components exist at all: it renders the same machine as the web app's Computers tab, from a different process, against a different backend.

## Conventions & gotchas

- `<script setup lang="ts">` SFCs + composables (module-level `ref` singletons), same as the web app; keep it free of app-specific logic so it stays reusable.
- The CSS cascade layer is named `primeng` (`installUi`'s `cssLayer.name` + `styles/primeng.css`): keep that name so `utilities` stays last and Tailwind utilities beat PrimeVue component styles.
- Semantic CSS variables (`--color-*`, `--radius-*`) are the styling contract: prefer them over hard-coded values. Consumed directly from source (no build step); `pnpm --filter @intentic/ui typecheck` runs `vue-tsc`.
- `CodeField` stacks a Shiki-highlighted `<pre>` and a transparent `<textarea>` in one grid cell, so every metric that can move a glyph is set once, in `styles/code.css` (`ui-code-field-box`), and applied to both. Split those two class lists and the text drifts off its own colours: silently, and only on the lines that wrap.
- **A class Tailwind cannot SEE is a class that ships as nothing.** Never build one by interpolation (`` `bg-${tone}` ``, `` `text-${size}` ``): write every variant out, or put it behind `@theme static`. This is the failure the series palette records in `semantic-colors.css`, and it is silent, the element simply renders unstyled.
- **Everything is on a scale, and off-scale is not an option for extensions.** `extension-surface.css` promises a class SURFACE to extension bundles and cannot enumerate arbitrary values, so a kit component drawn at `text-[0.65rem]` renders at a size no extension can match. Reach for `text-3xs`/`text-4xs`, `w-modal-*`, `max-w-read*`, `h-panel*`: and if the scale has no step for what you need, add one rather than an arbitrary value.
- **There is a gallery.** `/kit` in the dev server renders every component in every state and every scale as a ruler. Open it before adding a component, and after changing one: it is the only place two look-alike parts sit side by side, which is where drift becomes visible.
